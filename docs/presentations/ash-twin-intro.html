what it's made of

Deliberately small

The stack fits on one napkin. Everything else lives in the four layers we own: specs, actors, page objects, primitives. No test framework wrapping a test framework. No reporting service to babysit.

Playwright 1.49browser automation and test runner
TypeScript 5.7types on every domain shape and selector
Node 22runtime, native ESM, native fetch
mysql2direct DB verification against the tenant
dotenvper-tenant env for creds and DB config
Chromiumone engine, headed or headless, on CI or laptop

No Jest. No Mocha. No reporting SaaS. No framework-of-frameworks. If a dependency is not on this list, ash-twin does not need it.

the choice

Playwright, because iframes

Payment gateways render across cross-origin iframes: cybersource.com, checkout.com, cardinalcommerce.com. Any tool that cannot walk across those origins cannot test our checkout at all. That is the load-bearing fact.

🖼️

Cross-origin iframes work

Walks the Cybersource SDK across its swapping iframes, into 3DS challenge frames on Cardinal Commerce, and back. Cypress historically cannot. This alone decided the tool.

⏱️

Auto-wait, built in

No sleep(500). Locators retry until visible, enabled, and stable. Flaky tests stop being flaky.

🎬

Trace viewer

Every failure ships with a video, DOM snapshot, and network log. You debug from the artefact, not by re-running.

🧩

Native TS fixtures

Dependency injection is first class. customer, admin, db, resolver compose cleanly, per test, with automatic teardown.

📦

One binary

One driver, all engines. Chromium in CI, headed on a laptop for debugging, same code path.

🏛️

Microsoft-backed

Active weekly releases, first-class TypeScript, adopted by every major frontend team. Not legacy, not a hobby project.
